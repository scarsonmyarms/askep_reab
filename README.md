# Кодування діагнозів реабілітаційного випадку

Програма читає довідник (Додаток до наказу НСЗУ, xlsx) і допомагає обрати основний та супутні діагнози
відповідно до формули кодування (стовпець O) і Правил (наказ НСЗУ № 182 від 16.04.2026).

## Встановлення
```
pip install openpyxl
```
tkinter входить до стандартного Python для Windows/macOS; у Linux: `sudo apt install python3-tk`.

## Запуск
Графічний інтерфейс:
```
python app.py шлях\до\довідника.xlsx
```
Командний рядок (без інтерфейсу):
```
python coding_rules.py довідник.xlsx --period post --main I63.3 --comp G81.9 --comp R47 --list
```
`--period post|long` — післягострий / довготривалий; `--st-required` — коди S/T у формулах T90–T95 обов'язкові;
`--list` — показати список для наступного супутнього поля.

## Джерела даних
- **Довідник** (`tests/dod1.xlsx`): назви діагнозів (і категорії I–M, якщо немає файлу категорій НСЗУ).
- **Файли НСЗУ** — кладіть у ту саму папку, що й довідник (підхоплюються автоматично за назвою):
  «Перелік основних діагнозів», «Співвідношення коду основного діагнозу та формули…»,
  «Співвідношення коду додаткового діагнозу та формули…», «Перелік пар діагнозів хрестик та зірочка»,
  «Перелік діагнозів ПП, ФО, С, СП, Z» (категорії кодів; якщо є — категорії довідника не використовуються).
  З них беруться: хто може бути основним і за якої умови, формули (окремо для ролі основного та супутнього),
  пари †/*. Довідник у цьому режимі дає **лише назви й категорії I–M**: стовпці N, O і позначки †/* у назвах
  не використовуються. Код без формули у файлах НСЗУ вимог не має.
  Якщо файлів НСЗУ немає — працює лише довідник (стовпці N і O).
- Деталізовані коди з файлів НСЗУ (M54.16, R47.0 …) отримують назву й категорії батьківської рубрики
  довідника; рубрики, що мають уточнення (G54, R47, M54.1), окремими пунктами не показуються.
- Якщо код є і в рядку групи, і окремо (G54.2 у групі G54) — діє точніший запис.
- Діагноз поза довідником, введений з кодом МКХ (напр., «I10 Гіпертензія»), враховується лише за кодом.

## Поля супутніх діагнозів (за ролями)
1. **За формулою основного** — по полю на кожну вимогу формули основного, яку він не закриває сам (зокрема Діагноз_Z).
   Перше з них — «Супутній 1», до нього застосовується власна формула.
2. **Пара †/*** — для основного й діагнозів із полів 1, якщо пару ще не вказано.
3. **За формулою супутнього 1** — по полю на кожну вимогу, яку не закривають супутній 1 і інші вже обрані
   супутні (основний не враховується; поле пари, усі варіанти якого закривають вимогу, теж враховується).
4. Пари †/* для діагнозів із полів 3.
5. **Необов'язкові** поля (коморбідні стани) — завжди одне порожнє в кінці.

Нумерація суцільна (Супутній 1, 2, 3 …); список кожного поля містить лише діагнози, що відповідають його ролі.

## Стаціонар / амбулаторія
Перемикач «Умови». Правила кодування однакові (лист НСЗУ № 8575/8-15-26 від 01.04.2026, п. 3 вимог до обліку).
В амбулаторії додатково показується відповідність послугам **АР1/АР2, АР3-1, АР3-2, АР4** за діагнозами
(переліки — `ambulatory_services.json`): ✔ — основний діагноз у переліку; ⚠ — у переліку лише супутній
(у листі: «щонайменше один з переліку», без уточнення, чи має це бути основний); ✖ — жодного.
Позначка «Є запис СР1/СР2/СР3 за останні 3 місяці» визначає АР1 (коеф. 1,0) чи АР2 (0,7).
Інші критерії (направлення, епізод, ЕМЗ, кількість сесій, вимоги до закладу) програма не перевіряє — лише нагадує.

## Логіка
- Основні — лише ті, що можуть бути основними (стовпець N) у вибраному періоді.
- Супутній 1 — за формулою основного; супутні 2–8 — за формулами основного та супутнього 1
  (плюс парні коди †/* уже обраних). Формула перевіряється лише для основного та супутнього 1.
- «плюс» — окрема обов'язкова група; «та/або» і «або» — достатньо одного з варіантів
  (як у формулах нових файлів НСЗУ: «Діагноз_ПП AND (Діагноз_ФО OR Діагноз_С)»).
- У переліку кодів «та» — окрема обов'язкова група (T92.3: S43/S53/S63 **і** T11.2).
- У кожному випадку обов'язковий код **«Діагноз_Z» — Z50.x** (реабілітаційні процедури). СФЗ (Z47–Z99: Z74.x, Z99.x …) —
  окрема категорія, необов'язкова; у формулах НСЗУ не вимагається.
- Група вважається виконаною самим діагнозом, якщо він має відповідну категорію (I–M).
- Перевіряються: подвійне кодування †/*, несумісні поєднання (список `EXCLUSIONS` у `coding_rules.py`),
  повтори, збіг з основним. Діагноз поза довідником — коморбідний стан, у формулах не враховується.

## Тести
```
pip install pytest
pytest                                   # синтетичні тести (не потребують довідника)
pytest --xlsx=шлях\до\довідника.xlsx     # + регресійні тести на реальному довіднику
pytest -m "not gui"                      # без тестів інтерфейсу
```
Після запуску з реальним довідником у кінці виводиться розділ «Комбінації діагнозів, перевірені на реальному довіднику»
(основний, супутні, очікуваний і отриманий результат, причини ✖/⚠). Повний звіт по кожній комбінації: `pytest --show-reports`.
Лише тести довідника з назвами комбінацій: `pytest -m real -v`.

Реальний довідник також можна задати змінною середовища `REHAB_XLSX` або покласти `.xlsx` поруч з `app.py`.

## Розширення Chrome (`extension/`)
Невелике вікно для вибору діагнозів (та сама логіка, що й у програмі) і заповнення полів «Код діагнозу (МКХ-10 АМ)» на сторінці Askep.

Встановлення:
1. Згенеруйте дані довідника (після кожного оновлення `dod1.xlsx`):
   `python export_json.py tests/dod1.xlsx extension/directory.json`
2. Chrome → `chrome://extensions` → увімкнути «Режим розробника» → «Завантажити розпаковане» → папка `extension`.
3. Після змін у файлах розширення або `directory.json` — кнопка «Оновити» на картці розширення.

Як працює заповнення:
- поля шукаються за підписом «Код діагнозу» (id на кшталт `input-297` генерується сторінкою і змінюється; його можна задати в налаштуваннях як додатковий);
- у поле вводиться код, розширення чекає список варіантів і вибирає варіант із **точним** кодом (рубрика `R47` не підставляється як `R47.0` — таке поле треба обрати вручну);
- основний діагноз іде в перше вільне поле, супутні — у наступні; діагнози, які вже є на сторінці, пропускаються, тож після додавання нових блоків можна натиснути «Заповнити» ще раз;
- кнопка «Знайти поля» лише підсвічує знайдені поля, нічого не змінюючи;
- розширення нічого не зберігає і не надсилає — форму зберігає користувач.

Тести розширення: `tests/test_extension_parity.py` (JS = Python, потрібен Node.js) і `tests/test_extension_fill.py`
(заповнення на імітації сторінки, потрібно `pip install playwright` і `python -m playwright install chromium`).
